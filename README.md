# 교원인사 온톨로지

2026 교원인사 실무도우미(중등·초등)를 개념·법령·수치·절차·서식·Q&A 관계로 재구성한 단일 HTML 레퍼런스입니다. 원천 YAML을 검증·직렬화해 별도 서버 없이 열 수 있는 공개용 페이지를 만듭니다.

## 현재 제공 기능

- 중등·초등 학교급 선택과 학교급별 원문 쪽수 전환
- 업무명·법령·수치·본문·원문 쪽수·적용 범위 검색 및 초성 검색
- 장·학교급 필터를 지원하는 3D 지식지도와 노드 간 관계 탐색
- 개념, 절차, 수치, 서식, Q&A, 법령 근거를 연결한 상세 노드 화면
- 현행 법령 출처, 시행일, 검토 상태와 공식 원문 링크 표시
- 다크 모드와 모바일 화면 대응

## 공개 화면에 포함하는 정보

정식 공개본은 이용자가 업무를 판단하는 데 필요한 정보만 제공합니다.

- 중등교원·초등교원 학교급 선택과 현재 선택 상태
- 제도·수치·절차의 설명과 적용 범위
- 중등·초등 실무도우미의 원문 쪽수
- 법령명, 조문, 시행일, 현행 여부와 국가법령정보센터 공식 링크
- 해당 연도 실무도우미를 기본 기준으로 한 내용과 원문 위치
- 관련 법령 안내 및 지역별 적용 시 소속 시·도교육청 지침 확인 안내
- 자료 기준일과 출처 범위

공개본은 매년 발행되는 해당 연도 실무도우미를 업무의 기본 기준으로 제시합니다. 다만 교육청별 절차·서식·제출기한처럼 지역에 따라 달라질 수 있는 사항은 소속 시·도교육청의 같은 연도 지침과 시행 공문을 함께 안내하고, 법률적 판단이 필요한 사항은 관련 법령을 연결합니다.

직접 근거 조문이 아직 연결되지 않았다는 사정만으로 공개 화면에 오류나 미완성 경고를 표시하지 않습니다. 실무도우미와 현행 법령이 실제로 다른 경우에만 두 기준을 함께 확인하도록 안내합니다.

## 공개 화면에 포함하지 않는 개발 정보

다음 내용은 검증과 유지보수에 필요하지만 일반 이용자에게는 불필요하므로 생성 HTML에서 제외합니다.

- 법령 조회 도구명(`korean-law-mcp`)과 호출 방법
- 법령 데이터베이스 내부 식별자(MST, 법령ID, 행정규칙ID 등)
- 개발자용 검증 방법과 조회 과정
- 로컬 원본 경로, 임시 추출물, 작업 캐시
- 테스트 명령, 빌드 로그, 미공개 개발 이슈

`build.py`의 공개 직렬화 단계가 위 내부 메타데이터를 제거하고, 본문에 남은 도구명과 내부 식별자를 공개용 표현으로 정리합니다. YAML에는 재검증을 위한 내부 메타데이터를 유지합니다.

## scope 필드의 실제 역할

노드의 `scope`는 거의 전부 `공통`이며, 중등·초등용 콘텐츠를 분기하는 필터가 아닙니다. 실무도우미 중등판·초등판을 원문 대조한 결과(`tmp/source-intake/2026_교원인사_실무도우미_정밀분석.md` §6), 두 판본은 기준일(2026.3.1. vs 2026.2.15.)과 부록 구성만 다를 뿐 제도·수치·기준의 내용 골격은 사실상 동일합니다. 확인된 유일한 실질적 차이(계약제 교원 연장계약의 "동일과목 결원" 요건 — 중등만 적용, 초등은 표시과목이 없어 과목 무관)는 해당 노드(`nodes/ch7_계약제.yaml`의 계약제 교원 연장계약 4요건) 본문에 조건부 문장으로 직접 서술되어 있으며, 별도 scope 분리 노드를 두지 않습니다. 정밀분석 §7이 별도로 플래그한 "행정소송 제소기한 중등 90일·초등 30일" 표기 차이는 실제 학교급 차이가 아니라 실무도우미 요약본의 파싱 오류로 확인되어(교원지위법 §10④ 원문 대조 결과 30일 단일 기준, `num-appeal-lawsuit-deadline` 참조) scope 분리 대상에서 제외했습니다.

`scope`의 실제 역할은 `pages` 필드(중등/초등 원문 쪽수)와 짝을 이루어, 화면 상단 학교급 선택 시 표시되는 **원문 쪽수 표기를 전환**하는 용도입니다. 즉 "이 제도가 중등에만 있다"가 아니라 "이 내용을 실무도우미 몇 쪽에서 찾을 수 있는가"가 학교급에 따라 달라진다는 뜻입니다. 향후 신규 노드 작성 시 중등·초등 간 실질적 규정 차이를 발견하면 별도 노드로 분리하지 말고, 위 연장계약 노드처럼 본문에 조건부 서술로 반영하는 것을 기본 규칙으로 합니다.

## 법령 검증 절차

법령 보강에는 `korean-law-mcp`를 사용합니다.

1. 법령명 검색으로 현행 법령과 시행일을 확인합니다.
2. 관련 조문·별표 원문을 조회합니다.
3. 실무도우미의 설명과 현행 조문을 대조합니다.
4. 일치하면 `verified`, 일부만 확인되면 `partial`, 차이가 있으면 `conflict`, 추가 확인이 필요하면 `needs_review`로 기록합니다.
5. 연도별 업무지침처럼 법령 데이터베이스에서 조회되지 않는 기준은 공식 시행계획·공문 확인 사항으로 남깁니다.

`legal_review` 내부 구조:

- `state`: 검토 상태
- `applicable_as_of`: 적용 기준일
- `checked_at`: 확인일
- `method`: 개발자용 확인 방법
- `unresolved`: 남은 확인 사항
- `applicability`: 적용 범위
- `sources`: 법령명·조문·시행일·공식 링크와 내부 재조회 식별자

## 빌드

```powershell
py -B build.py
```

산출물:

```text
dist/교원인사_온톨로지.html
```

`dist/`는 생성 산출물입니다. 공개 화면에는 내부 법령 조회 도구명, 데이터베이스 식별자, 로컬 경로와 검증용 메타데이터를 포함하지 않으며, 원천 YAML의 `legal_review`에는 재검증에 필요한 내부 정보가 남습니다.

## 저장소 구성

- `nodes/`: 교원인사 개념·절차·수치·서식·Q&A 원천 YAML
- `edges.yaml`: 노드 간 관계
- `schema.py`: 원천 데이터와 그래프 구조 검증
- `layout.py`, `search_index.py`: 지식지도 배치와 공개 검색 인덱스 생성
- `template.html`: 공개 단일 HTML 화면과 클라이언트 탐색 기능
- `build.py`: 검증, 공개용 메타데이터 정리, 레이아웃·검색 인덱스 생성, HTML 출력
- `tests/`: 스키마·빌드·레이아웃·검색·법령 검토 테스트

## Vercel 배포

`vercel.json`에 빌드 커맨드(`python3.14 build.py`)와 output 디렉터리(`dist`)를 지정해 두었습니다. Vercel 대시보드에서 이 저장소를 Import하면 별도 설정 없이 자동 인식됩니다(Framework Preset: Other). 배포 환경의 Python 버전이 `3.14` 명령을 제공하는지 최초 배포 로그에서 확인해야 합니다.

- 산출물 파일명이 `교원인사_온톨로지.html`이라 모든 경로를 이 파일로 라우팅하는 rewrite 규칙을 함께 넣었습니다. 앱 내부 이동은 해시 라우팅(`#/node/...` 등)이라 서버 라우팅과 무관하게 정상 동작합니다.
- 배포 빌드에 필요한 Python 패키지는 `requirements.txt`에 정의되어 있습니다. 현재 `vercel.json`의 빌드 커맨드는 의존성 설치를 별도로 수행하지 않으므로, Vercel 프로젝트의 설치 단계 또는 빌드 환경에 해당 패키지가 준비되어 있어야 합니다.
- 계정 연결·프로젝트 생성·환경 변수 등록은 사용자가 Vercel 대시보드에서 직접 진행합니다.

## 데이터 갱신 절차

1. 해당 연도 실무도우미와 공식 법령 원문을 기준으로 `nodes/`의 원천 YAML을 수정합니다.
2. `legal_review`에 검토 상태·기준일·확인일·공식 출처를 기록합니다.
3. 아래 테스트와 빌드를 실행합니다.
4. 생성 HTML에서 내부 조회 도구명과 식별자가 제거되었는지 확인한 뒤 배포합니다.

지역별 절차·서식·제출기한은 소속 시·도교육청의 같은 연도 지침과 시행 공문을 추가로 확인해야 하며, 공개 화면의 내용이 개별 사건에 대한 법률 자문을 대신하지는 않습니다.

## 검증

```powershell
py -m pytest -q
```

Windows에서 저장소의 `.pytest-tmp`에 대한 `WinError 5`가 발생하면, 저장소 임시 폴더를 사용하지 않도록 다음처럼 실행합니다.

```powershell
py -m pytest -q -o addopts= --basetemp test-tmp-codex
```

공개 산출물 추가 점검:

```powershell
rg -n -i "korean-law-mcp|MST|법령ID|행정규칙일련번호|행정규칙ID" dist
```

검색 결과가 없어야 공개·개발 정보 분리가 통과한 것입니다.
